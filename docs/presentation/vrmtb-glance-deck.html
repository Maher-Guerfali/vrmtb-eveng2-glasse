The problem

Everyone in the room is served except the person actually standing in it.

VR-MTB already covers three postures: an immersive station for the radiologist deep in the volume (Quest 3 / Vision Pro), a desktop dashboard for the standard participant, and a voice-only wearable for hands-free talking (Rokid).

The unserved persona is the surgeon, pathologist or oncologist at the table — or on the ward, three cases before theirs comes up — who will not put on a headset and often doesn't open a dashboard. In a hybrid board they lose situational awareness the moment they look away from the shared screen: which case, what stage, what was the Ki-67 again.

The Even G2 is purpose-built for exactly this posture: 35 g, looks like ordinary glasses, a private monochrome HUD only the wearer can read, and — critically for a clinical room — no camera and no speaker.

The device

No camera, no speaker — that's the pitch, not a limitation.

The missing camera removes the single biggest wearable-adoption blocker in a hospital: colleague and patient privacy. The missing speaker means the room never hears it — every card on this HUD is private by construction.

    What shipped · root cause

    "The app is controlling itself" — it wasn't. Nothing was listening.

    First real-device test: the HUD rendered correctly, cards looked right, and yet no touchpad tap or swipe did anything. The only thing visibly moving was a demo timer auto-advancing the mock board — which made the whole app look autonomous.

    The actual cause: the G2's OS drops every touch event unless at least one rendered container has isEventCapture set. Nothing in the SDK's docs flags this as required. Found and fixed on the physical device, not in theory — now every page flags its header container to capture input, and a related host quirk (a tap sometimes arriving with no event type at all) is handled the same place.

    This is also why the mock board now defaults to static, not auto-advancing — so a silent app and a controlled one are never visually indistinguishable again.

    06 / 14
    What shipped · navigation

    Browse, then commit.

    Swiping the patient list moves a local cursor only — it never touches what's active on anyone else's screen. Only an explicit tap commits the selection, and that tap broadcasts room-wide through the same channel the dashboard's own UI uses.

    Detail pages: summary first, swipe once for conditions and the board's question.

    07 / 14
    tap = dictate — visible in the footer
    What shipped · dictation

    Tap to talk. Tap again to save.

    Two engines, chosen automatically:

    • default phone's own speech engine — no key, no server
    • ?stt=proxy glasses mic → local proxy → OpenAI

    The API key is never in the glasses bundle. It's typed interactively into a launcher script and lives only in that process's memory — by design, no script or agent reads it from disk.

    08 / 14
    What shipped · hands-free

    "Next patient." Done — on every screen in the room.

    One continuous listener parses a small, deliberate vocabulary — open a screen, navigate cases, dictate a note, log a decision, read notes back. Ambient meeting conversation is silently ignored on purpose; only recognized phrases act.

    English and German. Every transcript segment also feeds a rolling caption card.

    09 / 14
    Talk (LiveKit) — real board only
    What shipped · live voice

    The room hears you, not just your notes.

    Every other feature only ever moves finished text. Talk is genuine two-way WebRTC audio — the same setMicrophoneEnabled call the dashboard's own mic button uses, so the G2 behaves as an ordinary room participant.

    Publishes the phone's mic via the WebView's standard audio capture — not the glasses' own mic, which streams out through a separate, non-standard PCM channel used for dictation instead.

    10 / 14
    Architecture

    We read the source before we wrote a line.

    The plan was a new vrmtb.hud topic the dashboard would need to add. After actually cloning and reading vr-mtb-web, that topic turned out unnecessary — everything a HUD needs already exists.

    ┌─ Even G2 ──────┐ BLE ┌─ Phone: glass-app ─┐ HTTPS/WSS ┌─ vr-mtb-web/backend ─┐ │ HUD · touchpad │◄─────►│ Even Hub SDK │────────────►│ rooms/join · session │ │ 4-mic · no cam │ │ livekit-client │ │ command channel │ └────────────────┘ └─────────────────────┘ └──┬──────────┬──────────┘ │ │ vr-mtb-web livekit-server (dashboard) (self-hosted SFU)

    Result: no dashboard PR needed. The glasses join the same room, curate PHI out of GET /api/session client-side, and write back through the exact selectPatient path the dashboard's own UI and voice commands already use — a full participant, not a mirror.
